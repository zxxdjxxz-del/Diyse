## 13. Character-Specific Animation Gaps for DIYSE

The generic libraries reduce baseline animation workload, but they do **not** replace class-identity animation work.

- **Cyanis:** Crest Knight weapon work and Crest Magus casting identity still need bespoke/retargeted motions.
- **Ilyra:** Wardrod + shield combat requires its own set; generic shield animations may supply a starting point only.

- **Nimera:** card handling, card casting, and Sixfold Knight-specific motions are still needed.
- **Vaelira:** dedicated bow/Prism Archer animation work is still needed.
- **Seyrik:** oversized greatsword/Ruin Vanguard/Ruin Healer motions need heavier bespoke treatment than the generic sword set.

## 14. Practical DIYSE Map-Building Strategy Established in This Chat

1. **Do not reconstruct the source maps.** Use the extracted material as a parts library.
2. Build **original DIYSE layouts** first around traversal, story beats, encounters, treasure, landmarks, and pacing.
3. Treat reusable environment systems as shared modules: water, fire, doors, trees, shadows, candles, interaction props.
4. Mix compatible pieces from multiple source families rather than making a DIYSE location visually identical to a source map.
5. Add original/generated DIYSE-specific architecture and landmarks where identity matters.
6. Use the CC0 prop kit aggressively for generic dressing so custom art effort is reserved for iconic content.
7. Use the CC0 animation libraries for shared locomotion/reactions/NPC activity, reserving custom animation effort for class/weapon identity.
8. Map size and encounter/treasure counts should be decided with **what can honestly be built** in mind, but asset availability should not dictate copied source layouts.

## 15. What Is Still Missing / Needs Original Work

- Permanent-party character models suitable for the target HD-2D anime presentation.
- Enemy models/rigs and boss-specific assets.
- Class- and weapon-specific combat animations listed above.
- DIYSE-specific landmark architecture, signage, iconography, banners/crests, Black Host identity pieces, and location-defining assets.
- Any missing biome-specific construction kits not sufficiently covered by current source families.
- Final engine materials/shaders, geometry, collision, nav, lighting implementation, and map composition.
- A clean rights decision for any extracted/non-CC0 source textures intended to survive beyond private prototyping.
